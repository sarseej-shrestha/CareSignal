# Slop Audit (Pass A — removals)

Generated by the `humanize-code` skill (jIrwinCline/humanize-code), Pass A, against
the full `app/`, `components/`, `lib/`, `scripts/`, `tests/` tree.

**Method:** mechanical/grep-verifiable patterns (stale logs, unused imports, dead
exports, defensive try/catch, type theater, TODO scaffolding) were checked
exhaustively across all 71 in-scope files. Structural patterns that need real
judgment (single-use helpers, wrapper-only functions, mixed naming/paradigms,
repeated blocks) got a targeted spot-check rather than a line-by-line read of
every file, since every mechanical category came back clean — this is a
codebase that has already been through multiple documented hardening passes
(load testing, FHIR validation rounds, a full Vitest suite), not a raw
first-draft AI dump. If you want a deeper T2/T3 pass, say so and it can run
as a follow-up.

**Total findings: 8 — all Tier 1. Zero T2, zero T3.**

## Tier 1 (rename / dead code / unused import / stale log)

### 1. Unused import — `scripts/train-hospitalization-model.ts:24`

```ts
import { predictRiskProbability } from "../lib/riskModel";
```

`predictRiskProbability` is never called in this file (confirmed by ESLint's
own `no-unused-vars` warning at this line). The hospitalization trainer uses
`assessRisk` from `lib/risk.ts` for its daily-risk feature, not the raw model
call.

**Proposed change:** delete the import line.

## Checked and clean (no findings)

- **Stale debug logs (T1 #1):** every `console.log` in the tree lives in
  `scripts/*.ts` (train-risk-model.ts, train-hospitalization-model.ts,
  load-test.ts, demo-trigger.ts, estimate-alert-volume.ts,
  set-live-demo-number.ts) — these are CLI tools whose stdout output *is*
  their interface, not leftover debugging. The one `console.warn` in
  `app/api/twilio/inbound/route.ts:207` is an intentional runtime warning
  (missing `TWILIO_AUTH_TOKEN`), not stale.
- **Unused imports (T1 #2) elsewhere:** ESLint's `no-unused-vars` is active
  project-wide and came back clean except finding #1 above.
- **Dead parameters (T1 #4):** no unused function parameters found beyond
  what ESLint already flags in test files (`tests/unit/ai.test.ts:12`,
  `_opts`) — out of scope per the catalog ("Test quality... don't touch
  tests under this skill").
- **Over-commenting (T1 #5):** the codebase already runs a strong "why, not
  what" comment culture (per CLAUDE.md and visible throughout); no comments
  found that merely restate the following line.
- **Defensive try/catch around safe ops (T2 #9):** all 12 `try/catch` blocks
  in the tree wrap real I/O — `fetch`, Prisma writes, the Twilio
  `formData()` parse, the Groq AI calls — none wrap something that can't
  throw.
- **Type theater (T2 #12):** the three `as unknown as X` casts in the tree
  (`lib/riskModel.ts:22`, `lib/hospitalizationModel.ts:19`,
  `lib/db.ts:3`) are the standard "cast a loaded JSON blob to its typed
  shape" and "Prisma globalThis singleton" patterns — idiomatic, not
  academic over-typing.
- **"Future-proof" stubs / TODO scaffolding (T2 #13):** zero `TODO`,
  `FIXME`, `HACK`, or `XXX` markers anywhere in `app/`, `components/`,
  `lib/`, `scripts/`.
- **Repeated blocks (T3 #14):** the one known duplication —
  `scripts/train-risk-model.ts`'s inlined copy of `lib/riskFeatures.ts`'s
  extraction logic — is documented in-file (line 132: "kept byte-for-byte
  equivalent to lib/riskFeatures.ts") and in `CLAUDE.md` as intentional
  (tsx module-resolution constraint on standalone scripts). Not proposed
  for extraction.
- **Two-layer risk architecture:** `lib/riskEngine.ts` (rules) and
  `lib/riskModel.ts` (trained classifier), combined in `lib/risk.ts`, is the
  documented two-layer design, not redundant code — not flagged.
- **Independent simulators:** `lib/independentPatientSimulator.ts` and
  `scripts/train-risk-model.ts`'s own simulation logic are deliberately
  separate (different RNG, different mechanism) per
  `docs/model-calibration.md`'s training-data-circularity section — not
  proposed for consolidation.
- **No `prisma.$transaction()` in `lib/inbound.ts`:** documented, tested
  decision (`docs/load-test-results.md`) — not flagged as a missing
  defensive-coding gap.
